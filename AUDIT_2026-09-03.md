## Починено в этом коммите (по убыванию веса)

### Ядро исполнения — деньги

1. **−1007/−1006 «execution status unknown» на 4xx считались отказом**
   (`BinanceFuturesAdapter.classifyError`). Вход мог налиться, а бот — не поставить стоп и не
   записать позицию; следующий проход видел «чужую» позицию с riskUsd=0, которую ремонт не трогает.
   Теперь эти коды — неоднозначность при любом HTTP-статусе, плейсер пробует по id.
2. **Пред-запрос плейсера был вне обработки неоднозначности** (`IdempotentOrderPlacer.place`).
   Таймаут на GET перед постановкой стопа → «стоп отказан» → рыночное закрытие только что открытой
   позиции; тот же таймаут перед входом → ложный халт «исход неизвестен». Теперь: пред-запрос
   повторяется, при провале — «ничего не отправлено» (не неоднозначность); координатор повторяет
   стоп 3 раза с секундной паузой только на безопасных отказах (соединение не открылось, 429/418),
   вход — просто отказ без халта.
3. **Сбой на этапе соединения (DNS, connect timeout) считался неоднозначной отправкой** →
   ложный «entry outcome unknown» халт. Теперь `ExchangeException.neverSent`.
4. **Позиция без записи после «unknown-after-send» или падения между филлом и стопом** оставалась
   голой навсегда (ремонт требует riskUsd>0). Добавлены **намерения входа** (`EntryIntents`,
   файл `entry-intents.json` рядом с леджером): план пишется ДО отправки входа, стирается когда стоп
   встал. Reconciler усыновляет позицию по намерению с плановым стопом и тут же его ставит.
   `unknownAfterSend` теперь сначала 5 секунд опрашивает биржу — если позиция есть, защищает её как
   обычный филл, без халта.
5. **Повторный сигнал с тем же id** (перепроигрывание книги, старый FILLED-ордер под тем же id)
   усыновлялся как «сегодняшний филл» или мог налиться второй раз (Binance держит id уникальным
   только среди ОТКРЫТЫХ ордеров). Теперь терминальный ордер старше 10 минут под этим id = отказ.
6. **Сбой чтения после `-4116` (дубликат = ордер ЕСТЬ)** превращал налившийся вход в «отказ».
   Теперь пробы по id, потом неоднозначность.
7. **Одно пустое чтение positionRisk стирало книгу, леджер и все stop-id** за проход. Теперь пустой
   список при ненулевом нереализованном PnL = непроверенное чтение (проход считается слепым,
   книга не тронута); исчезновение книги из 3+ позиций требует двух пустых чтений подряд.
8. **Сбой чтения ордеров по одному символу ронял весь проход после реалайна книги** — призраки
   и их строки журнала терялись. Теперь один символ = одна «неподтверждённая» отметка.
9. **Сбой отмены защитных ордеров после подтверждённого закрытия** выбрасывался до `registerClose`:
   реальный выход повторялся как «неудачное закрытие» и не попадал в журнал. Теперь закрытие
   записывается, остатки — работа чистки сирот.
10. **Сироты на плоских небронированных символах никогда не чистились** (съедают лимит ~33
    условных ордеров). Раз в 20 проходов — чистка по всему счёту (`openOrdersAll`), только
    reduce-only/closePosition, старше грейса.
11. **Ручная сделка владельца со стопом из приложения** получала riskUsd>0 в леджере и считалась
    «своей»: килсвитч закрыл бы её, ремонт стопа трогал бы её, сканер (см. ниже) закрывал бы.
    Владение теперь = префикс `bt-` у stop-id (`ClientOrderIdFactory.isOurs`) во всех местах.

## Решения владельца (деньги/конфиг — не трогал)

1. **DIP-входы без временного потолка.** По правилу как написано, дрейфующая монета занимает слот
   ~19 дней в среднем, >30 дней — в четверти случаев (оценка линзы по ATR ALGO). Лаба мерила
   dip_bounce_v1 как «купить просадку ≥10%, ждать +3%» — живой выход другой (стоп −2×ATR, тейк
   1.75R, «триггер перестал держаться»). Вердикт по журналу надо считать раздельно по триггеру.
2. **DIP-триггер недостижим при 30д-доходности > +2%**: такая монета помечается `trend`, не
   проходит near-high (она по определению ≥10% ниже максимума) и выбывает. Живой dip-форвард —
   не dip_bounce_v1. Менять = менять измеренную конструкцию; твоё слово.
3. **Округление вверх на один шаг лота** при провале $5: TWT сел бы 10 лотами с риском $0.70
   (+1.7% к бюджету), EGLD 1.1 лота (+6.8%) — внутри уже принятого 20%-го допуска на слиппедж.
   Дало бы 1-4 входа/проход, которые сейчас отбрасываются. Флаг не делал — это про риск на сделку.
4. **Килсвитч −3% при 15×0.5%**: при ~70% депозита в номинале коррелированных лонгов флаттен всей
   книги ждёт примерно на −4.3% дне альт-корзины — обычный красный день. Частота предсказуема из
   лабы (651 день), не измерялась. Окно подтверждения 20 с (п.18) — инженерное, порог — твой.
5. **MAX_POSITIONS=15 при $137**: 1-4 кандидата за проход не размещаемы по $5; депозит остаётся
   главным тормозом (как и 28.08).
6. **Медвежий пул**: после п.29 форвард медвежьих дней фактически начинается заново (раньше тест
   шёл на квинтиле top-100).
