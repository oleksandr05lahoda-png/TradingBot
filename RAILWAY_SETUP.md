# Railway 24/7 — пошаговая настройка

Бот в облаке торгует РЕАЛЬНЫМИ деньгами без присмотра. Порядок важен: пропустишь
шаг — либо не запустится, либо запустится небезопасно.

## Что уже готово в коде
- `Dockerfile` — образ с Java 21 + Python в одном контейнере (бот + сканер).
- `tools/docker-entrypoint.sh` — запускает обе части, ротирует книгу, кладёт
  память о стопах на постоянный диск, роняет контейнер если одна часть умерла
  (платформа перезапустит обе вместе).
- Сканер читает ключи из переменных окружения (в облаке нет local.env).
- Fat jar `bot.jar` собирается через shadowJar — проверено.

## ЖЕЛЕЗНОЕ ПРАВИЛО ПЕРЕД ЗАПУСКОМ
**Бот на ноуте должен быть ВЫКЛЮЧЕН, когда работает облачный.** Два бота на одном
счёте дерутся за позиции реальными деньгами. Авто-запуск на ноуте уже удалён, но
если запускал вручную — сначала `tools\stop-real.ps1`. Бэкап-защита есть
(реконсайлер заметит расхождение размера и встанет в халт), но полагаться на неё
нельзя. Один бот на один счёт. Точка.

## Шаги (твои — только ты можешь)

### 1. Запушить ветку на GitHub
Ветка `feature/testnet-risk-core` (61 коммит) лежит только на ноуте. Пуш:
    git push -u origin feature/testnet-risk-core
⚠️ НЕ мержить в `main` и НЕ пушить в `main`: старый Railway-сервис следит за `main`
и держит боевые ключи легаси-бота — мерж авто-задеплоит туда наш код. Только
feature-ветка.

### 2. Railway → Pro ($20/мес)
Статичные IP есть только на Pro. Без них ключ Binance (с обязательным IP-whitelist)
работать не будет. Hobby не подходит — снять whitelist нельзя, Binance удалит ключ.

### 3. Новый сервис (не трогать старый TradingBot)
- New Service → Deploy from GitHub repo → выбрать репозиторий, ветку
  `feature/testnet-risk-core`.
- Builder оставить как есть — Railway увидит Dockerfile и соберёт по нему.

### 4. Постоянный диск
- Service → Settings → Volumes → добавить том, mount path: `/app/data`.
- Без него при каждом перезапуске теряется память о стопах → бот просыпается в
  халте и не торгует.

### 5. Static IPs → в whitelist Binance
- Service → Settings → Networking → Enable Static IPs (HA даёт 3 адреса).
- Redeploy, скопировать 3 адреса.
- Binance → API Management → изменить ключ → вписать эти 3 адреса в whitelist
  (польские убрать — с ноута торговать больше не будешь).

### 6. Переменные окружения (Service → Variables)
Скопировать значения из local.env. ИМЕНА строго такие:
    BINANCE_REAL_API_KEY=<реальный ключ>
    BINANCE_REAL_API_SECRET=<реальный секрет>
    TELEGRAM_BOT_TOKEN=<токен>
    TELEGRAM_CHAT_ID=<chat id>
    REAL_TRADING=ARMED
    REAL_MODE=observe            # ПЕРВЫЙ запуск — наблюдение, не торговля
    MAX_POSITIONS=10
    DEFAULT_LEVERAGE=2
    TP_R_MULTIPLE=1.75
⚠️ REAL_MODE=observe на первый деплой: бот прочитает счёт, покажет позиции,
НИЧЕГО не откроет. Проверяешь по логу и Telegram, что всё верно.

### 7. Первый деплой = наблюдение
- Deploy. Смотреть логи сервиса: должно быть
  `REAL EXCHANGE — REAL MONEY. Mode: OBSERVE` и `adopted from the exchange`.
- В Telegram придёт `[REAL OBSERVE]`.
- Если ключ отвергнут по IP — значит статичные адреса не совпали с whitelist,
  вернуться к шагу 5.

### 8. Включить торговлю
- Когда наблюдательный запуск чистый: Variables → REAL_MODE = `trade` → Redeploy.
- С этого момента сканер набирает позиции, бот исполняет, круглосуточно.

## Экстренная остановка (в облаке нет stop-real.ps1)
1. Railway → сервис → Remove / Stop deployment. ИЛИ
2. Binance → API Management → удалить ключ (работает даже если Railway недоступен —
   бот теряет доступ к бирже мгновенно). Позиции остаются под биржевыми стопами.

## Что это НЕ делает
Не улучшает стратегию и не «учит» бота. Он крутит то же правило круглосуточно.
Данные для обучения копит дип-лаборатория в Supabase — независимо от облака.
Смысл Railway один: бот не спит вместе с ноутом.

## Команды оператора в Telegram (с 22.08)

Бот слушает чат из `TELEGRAM_CHAT_ID` (только его; чужие команды игнорируются без ответа):

- `/status` — что держит, халт/нет, хоулд биржи, килсвитч. Снимок главного цикла, обновляется каждые 30 с.
- `/halt` — перестать открывать новое. Закрытия, стопы и тейки работают. Снимается `/resume`.
- `/resume` — снять халт после того, как вы посмотрели причину. **Не снимает `REAL_MODE=observe`** —
  это режим окружения, включается только `REAL_MODE=trade` + Restart.

Ответы начинаются с `[REAL TRADE]` / `[REAL OBSERVE]` / `[DEMO]`: демо и боевой бот могут делить один чат.
Если команды не отвечают — токен слушает кто-то ещё (второй бот, вебхук n8n): дайте боевому боту отдельный токен.

**Экстренная остановка — в этом порядке:** `/halt` (мягко, позиции под стопами) → Remove deployment
(бот стоит, стопы на бирже) → отозвать ключ (самое грубое).
